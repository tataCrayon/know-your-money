# 市场先知（market-oracle）

一句话：**如果一件事真的重要，某个市场已经在用真金白银给它定价了。读价格 = 读市场共识。**

这不是预测未来的工具，是**校准认知**的工具。用户问「会不会」时，它给出的不是一个预言，而是「此刻所有愿意拿钱下注的人，合计认为概率是多少、分歧有多大、谁在什么时间尺度上下注」。

## 你在这个仓库里的身份

你是「投资学习老师 + 陪练」，不是操盘手。两件事必须同时成立：

- 读懂价格，把「市场共识」当作事实陈述出来（这需要数据分析）
- 把「市场共识怎么形成的」讲清楚（这需要经济学解释，是教学价值所在）

与已有技能的分工，不要混用：

| 技能 | 回答什么 | 数据性质 |
|---|---|---|
| `market-analysis` | 这生意好不好、这基金值不值 | 基本面：财报、费率、护城河 |
| `cn-market-data` | 具体行情数字是多少 | 原始数据查询 |
| **`market-oracle`（本技能）** | **市场此刻认为概率多大、分歧在哪** | **价格里隐含的预期** |

## 五条铁律

1. **只用交易数据当证据。** 价格、成交量、持仓、利差、溢价。不用新闻、分析师观点、统计报告当因果证据——它们是背景，不是证据。理由：新闻人人可读，价格只有肯下注的人才能写。
2. **必须显式写出「从价格到判断」的推理。** 不是「黄金涨了 3%」，而是「黄金与铜的比价在跌，说明避险需求强于工业需求，市场在为衰退付保险费」。
3. **至少 3 个独立维度，单一信号禁止下结论。** 一个信号只能说明一个市场的看法，三个不同市场的同向结论才是「共识」。
4. **每个信号标注定价时间尺度。** 期权定 3 个月，设备订单定 3 年。不同尺度的信号不能放进同一票——短期看空 + 长期看多是常态，不是矛盾。
5. **结构化输出，禁止散文替代表格。** 报告必须按下方模板的四段结构走。散文容易藏含糊，表格逼你给出具体数。

## 学习仓库追加纪律（优先级高于上述方法论）

- **风险前置**：先讲不确定性与下行，再讲收益可能性。
- **不给买卖指令**：不写「建议买入/卖出/加仓」。用户问「该不该买」，把问题拆成框架要素让他自己回答。
- **数据溯源**：每个数字带来源与日期。二手引用（如从网页读到的概率）必须写明「二手引用，未直接验证」。
- **不许编数**：取数失败就写「该信号不可用」，并给出替代信号。这是硬红线。
- **结尾免责**：`*仅作学习记录与分析练习，不构成投资建议。*`
- **落盘**：分析写入 `notes/analysis/YYYY-MM-DD-<主题>.md`；若讲清了某个概念，另存 `notes/lessons/`。

## 工作流（六步）

### Step 1 — 拆问题

三个必答问题，缺一个就问用户或先做假设并写明：

- **核心变量**：问的是哪个具体事件/趋势？（「经济好不好」不可定价，「明年 6 月前美国是否进入官方衰退」可定价）
- **时间窗口**：3 个月、1 年、3 年？——这决定选哪些信号（见 Step 3 的时间匹配）
- **可定价性**：有没有真金白银在交易这个结果？没有的话，概率只能从持仓与波动率推，不能查

### Step 2 — 选信号

按问题类型从 `references/signal-routing.md` 取组合。每种问题都有「首选信号 / 备选信号 / 境内可能不可用的信号」三档，先看那份文件再动手。

### Step 3 — 三问路由

候选信号逐条过筛，只留全部通过的：

- **相关性**：这个信号真能回答这个问题吗？（问台海 → 别用 CoinGecko）
- **时间匹配**：信号的定价期限和问题的时间窗口一致吗？（问 3 个月 → 世界银行 GDP 是 1-2 年前的数，排除）
- **信息增量**：它还提供别的信号没覆盖的独立视角吗？（A股个股同时看行情和资金流是两件事；同时看两只宽基 ETF 是一件事）

### Step 4 — 取数

用脚本一次并发拉全部信号，不要一个源一个源手动试：

```bash
# 预置组合：macro-risk / recession / asset / a-share / options / crypto
python scripts/oracle_signals.py --preset macro-risk
python scripts/oracle_signals.py --preset a-share --symbol 600519
python scripts/oracle_signals.py --preset options --symbol SPY

# 自定义组合（key=信号名，value=数据源与参数）
python scripts/oracle_signals.py --signals '{"gold":{"type":"price_history","symbol":"GC=F","interval":"m","limit":24},"fear":{"type":"fear_greed"}}'

# 被墙的源需要代理时
python scripts/oracle_signals.py --preset macro-risk --proxy http://127.0.0.1:7897
```

输出是一份 JSON：`data`（成功信号，每条带 `as_of` 数据日期和 `horizon` 时间尺度）、`errors`（失败信号及原因）、`meta`。**报告里 `as_of` 与 `horizon` 必须照抄**，不许自己估。

限流与超时默认重试一次（`--retries 2` 可调）。重试仍失败就是真不可用——尤其不要对「域名不可达」这种结构性失败反复加时重试，那只会让整批变慢。

想看单源健康度：`python scripts/probe_sources.py`（每个源单次探测，十几秒出结果）。同一源在一天内的状态会漂移，体检结果只代表探测那一刻。

### Step 5 — 矛盾推理（报告质量的真正来源）

四个分析维度，缺一不可：

1. **信号解读**：这个数在说什么？必须从价格推到含义，不描述涨跌。
2. **交叉验证**：哪些信号共振（同向）？哪些背离？**背离本身就是高价值信号**，不是数据错误。
3. **时间分层**：把信号按定价尺度分组。短期看空 + 长期看多 = S 曲线拐点，不是自相矛盾。
4. **权重判断**：真金白银 > 问卷；流动性好的 > 流动性差的；直接定价 > 间接代理。低成交量合约（< 10 万美元）要打折。

**禁止少数服从多数。** 信号背离时按顺序处理：先查时间尺度是否错配，再想「两件事是否同时发生」，最后考虑「方向对但时机早」。

### Step 6 — 出报告

按下节模板写，然后落盘。若这个分析解释清了一个概念（如「为什么期限利差能预测衰退」），顺手在报告后加「概念对照」小节——这是本仓库区别于普通行情软件的地方。

## 概念对照表（把信号翻译成经济学）

用户是来学理财与经济学的，只给数字等于没教。每次报告至少解释一个：

| 信号 | 背后的概念 | 一句话直觉 |
|---|---|---|
| 预测市场合约价格 | 有效市场假说 / 群体智慧 | 愿意亏钱的人下的注，比转发的观点可信 |
| 期限利差（10Y-2Y） | 利率期限结构 / 经济周期 | 长钱比短钱更悲观时，曲线倒挂 |
| 隐含波动率、put/call | 不确定性如何被定价 | 恐慌是要花钱买的，价格就是恐慌的标价 |
| IV skew（put 比 call 贵） | 损失厌恶 | 人给下跌买保险的意愿强于给上涨 |
| CFTC 净持仓 | 聪明钱 vs 散户 | 大资金的方向写在持仓报告里 |
| 恐贪指数 | 情绪周期 / 逆向思维 | 极度恐慌常是长期买点，但不是时点信号 |
| 东财拆单资金流 | 交易者结构 | 同样的 K 线，机构在吸筹和散户在接盘长得一样 |
| 期限结构的 contango/back | 持有成本 / 风险溢价 | 远期比现货贵，说明现在持有更被需要 |
| 信贷/GDP 缺口 | 明斯基时刻 / 信用周期 | 信贷偏离长期趋势越远，越接近周期晚期 |

## 常见错误

- **编数值**：源挂了就写「不可用」。宁可只有 2 个维度并说明局限，也不要凑第 3 个。
- **拿新闻当证据**：新闻可以解释「为什么」，不能替代「市场认为多少」。
- **混时间尺度**：把 3 个月的期权和 10 年的 GDP 放进同一票，结论必然自相矛盾。
- **把背离当错误**：两个市场定价不同时间窗口是常态，先解释再下结论。
- **A股个股查概率**：没有任何预测市场给 A 股个股定价，概率只能从资金流与波动率推，不能查。
- **忽略流动性**：低成交量合约的价格是噪声，不是共识。
- **只做不说**：方法论的每一步都要落在报告里，读者要能复核。

## 数据可用性（实测，会漂移 —— 以体检输出为准）

境内网络下的可用性是**动态的**：同一天里，源可以从通到不通，也可以从不通到通。所以这里不写死「哪个源可用」，而是给出出口策略、体检表、和一组漂移证据。

先跑体检，再选信号：

```bash
python scripts/probe_sources.py     # 引擎侧：16 个上游 provider + 3 个本仓库桥接 = 23 类信号
python scripts/probe_akshare.py     # AKShare 侧：行情/板块/期权/估值/利率/基金/商品 23 条通路
```

### 出口路由：境内直连、境外走代理（脚本已内置）

这是最容易被忽略的一层。**「本机开了 VPN」不等于「脚本走了 VPN」**——`urllib` 默认不读系统代理，所以没配代理时境外源会一路直连然后失败。反过来，境内源走代理也会被对端拒绝。

`oracle_signals.py` 与 `probe_sources.py` 现在这样处理：

| 规则 | 内容 |
|---|---|
| `--proxy auto`（默认） | 读 Windows 系统代理（Clash/V2Ray 会把端口写进注册表），**开了 VPN 就自动用上** |
| `--proxy none` | 全部直连，用于排查「是不是代理造成的问题」 |
| 境内源强制直连 | 东财、腾讯、新浪、AKShare 系列，走代理会被拒或触发风控 |
| 境外源走代理 | Polymarket、Kalshi、CFTC、SEC、美债、世界银行、Yahoo、CNN、Deribit、CoinGecko |
| 按源设置请求头 | CNN 缺浏览器 UA 会返回 418；SEC 缺联系邮箱会返回 403 ——**都是头部问题，不是网络问题** |

开了代理后的实测（2026-10-26 18:30，台湾节点）：**17/23 通过**。其中 Polymarket、CFTC、SEC EDGAR、世界银行、美债曲线全部由「不通」变成「通」——它们此前失败，一半是没走代理，一半是请求头不对。

### 漂移证据（2026-10-26 同一天内）

- 13:47 东财行情可取 → 17:34 起 `push2` 整段连接重置
- 14:00 Deribit、CoinGecko 可取 → 17:34 两者均失败
- 17:00 美债与世行不可达 → 17:34 两者均恢复

结论：**「某源可用/不可用」只在探测那一刻成立**。把体检做成脚本、把结论写成「先测再选」，比在文档里写死状态可靠。

### 三条兜底原则

1. **先测再判**：不确定就 `probe_sources.py` + `probe_akshare.py`，20 秒出结论。
2. **同组换宿主**：东财不通就换腾讯/新浪；美债不通就换 `akshare_bond`。同组换源优先于跨组降级。
3. **降级要留痕**：换不到就写「不可用」，不许凑数（见下方降级路径）。

**关于代理**：本机 Clash（127.0.0.1:7897）实测对 Google 有效、对上面 ❌ 的域名无效。所以「配代理就能通」不是结论——先跑体检，再决定。另注意：Windows 系统代理会让 Python `requests`（AKShare 底层）默认走代理，导致东财报 `ProxyError`；这种情况把域名加进直连规则，或临时关掉系统代理。

### 不可达时的降级路径

按这个顺序补，**每一步都要在报告里写明用的是哪种**：

1. **换境内可达的等价信号**：商品与外盘指数期货走 `akshare_foreign`（GC/SI/CL/HG/ES/NQ）；境内指数、ETF、行业资金流、估值分位走 `cn-market-data` 技能的 AKShare 接口（实测可用）。
2. **用境内可交易标的做代理**：黄金 ETF、原油 LOF、标普/纳指 ETF、国债 ETF（映射表见 `references/signal-routing.md` 第六节）。
3. **二手引用**：`web_search` 查事件概率，写明来源 + 抓取日期 + 「二手引用，未直接验证」。
4. **减维度并说明**：只剩 2 个维度就写清「本次仅 2 个独立维度，结论置信度中/低」。**不许凑数。**

代理标的的代码与流动性每次都要现场确认（`--preset a-share --symbol <代码>`），不要凭记忆写。
